## 8. v0.31 → v0.32 methodology

The central rehearsal started from the exact deployed v0.31 artifact:

1. extract deployment commit `867170e476793112d0197c3d38a5b98321a51064`;
2. assert the released source tag and production tree/build identities;
3. create fresh persistent Chromium profiles with realistic schema-5 roster history, diary actuals, employment/pay history, pay checks, calendar settings and device preferences;
4. install and activate the exact v0.31 service worker/cache;
5. fully restart the browser on v0.31;
6. publish the exact production-form RC bundle on the same isolated origin;
7. prove the RC installs as a verified waiting build while v0.31 remains coherent;
8. reload while waiting and prove v0.31 remains active;
9. explicitly activate through the user-controlled update path;
10. compare exact localStorage/IndexedDB envelope bytes, canonical generation/fingerprint and semantic surfaces;
11. browse Home, Search and duty details;
12. close/reopen cold offline;
13. repeat for local-only and remembered-key encrypted variants;
14. import an authentic v0.31 schema-4 `.rosterbot` backup into a fresh RC profile.

No canonical migration is required from released v0.31 to v0.32: both use schema 5. The application version change does not manufacture a personal-state generation.
